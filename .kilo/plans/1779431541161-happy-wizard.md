## Architecture facts to include

### Module loading

Source files to reference:

- `module.json`
- `scripts/module.mjs`
- `scripts/constants.mjs`
- `scripts/settings.mjs`

Key points:

- Foundry loads `scripts/lib/face-api.min.js` first, then `scripts/module.mjs` as an ES module.
- CSS comes from `styles/multi-tokenart.css`.
- Language packs are `lang/en.json` and `lang/ru.json`.
- Module socket support is enabled in `module.json`.
- `MODULE_ID` is `multi-tokenart`.
- The module targets Foundry VTT v13.

### Hooks and entrypoint flow

Source file:

- `scripts/module.mjs`

Describe these hooks:

- `init`
  - registers settings via `registerSettings()`
  - registers Token HUD button hooks
  - registers actor sheet header buttons
  - exposes module API
  - preloads Handlebars partials/templates
- `ready`
  - applies system HP preset when defaults are still active
  - registers file socket handlers
  - re-exposes API defensively
  - forces core `dynamicTokenRingScaling` to `grid` for GMs
  - exposes `globalThis.MultiTokenArtDebug`
- `updateActor` and `updateToken`
  - detect configured HP path changes
  - schedule debounced auto activation
- `createActiveEffect`, `updateActiveEffect`, `deleteActiveEffect`
  - schedule auto activation for status/state changes
- `createToken`
  - initializes token and portrait images from active/default/random state
  - applies Dynamic Ring and linked portrait behavior
  - runs auto activation
- `renderActorSheet`
  - swaps visible sheet portrait when token-specific portrait is active

Important implementation note:

- `scheduleAutoActivationForActor()` intentionally uses the actor object received from hooks instead of `game.actors.get(actorId)` so unlinked tokens keep synthetic actor delta flags.
- Automation is run only by the active GM, or by a permitted non-GM only when no active GM exists.

### Auto activation

Source files:

- `scripts/logic/AutoActivation.mjs`
- `scripts/utils/hp-resolver.mjs`
- `scripts/settings.mjs`

Describe priority order in `findBestImageForHp()`:

1. Dead image: HP `<= 0` and `autoEnable.die`.
2. Status image: configured status matches active actor/token status data.
3. Wounded image: HP percent below configured threshold; most severe threshold wins.
4. Manual image persistence: keep current active non-special image.
5. Restore pre-condition image after leaving special state.
6. Default image fallback.

Describe status matching:

- Checks effect `name`, `label`, `statusId`, `slug`, `statuses`, and token effects.
- Uses locale compare with accent sensitivity.

Describe apply behavior:

- `applyTokenImageById()` updates token texture source and scale, active image flags, Dynamic Ring payload, `lastUpdate`, and linked token prototype state.
- `applyPortraitById()` updates actor `img` and token-specific active portrait flags.
- Link mode maps token image to portrait image by sorted visual index.

### Random mode

Source file:

- `scripts/logic/RandomMode.mjs`

Describe:

- `pickRandomImage()` excludes images with `autoEnable.enabled` from the random pool.
- If all images are auto-enabled, it falls back to the default image.
- `sortImagesByOrder()` sorts by `sort`.

### Auto rotate

Source file:

- `scripts/logic/AutoRotate.mjs`

Describe:

- Stores original token rotation in `originalRotation`.
- Rotates to `270` when HP is zero and auto rotate is enabled.
- Restores original rotation when healed or disabled.

### Dynamic Ring

Source file:

- `scripts/logic/DynamicRing.mjs`

Describe:

- Builds token update payloads rather than directly applying all updates.
- Snapshots original ring state in `originalRing` before enabling/disabling.
- `getDynamicRingUpdate()` applies ring colors, background, and subject scale.
- `getDisableRingUpdate()` explicitly disables ring while preserving original state.
- `getRestoreRingUpdate()` clears stale subject texture and removes original snapshot flag.
- `ready` hook forces core Dynamic Ring scaling to `grid` for correct rendering.

### Token generation

Source files:

- `scripts/logic/AutoTokenService.mjs`
- `scripts/apps/MultiTokenArtManager.mjs`
- `models/tiny_face_detector_model-weights_manifest.json`
- `scripts/lib/face-api.min.js`

Describe automatic generation:

- Uses singleton `AutoTokenService`.
- Loads TinyFaceDetector from `modules/multi-tokenart/models` once.
- `createTokenBlob()` loads source image, tries face detection on raw image, then proxy canvas with gray background.
- Falls back to image center when no face is detected.
- Produces WebP token blob from a circular 512 canvas.

Describe manual generation:

- Opened from `MultiTokenArtManager`.
- Uses an inline Dialog with stage and preview canvases.
- Supports crop lock, zoom/pan, preview zoom, additive/subtractive alpha polygons, custom frame image, frame offset/scale, optional white background removal.
- Uses `createTokenBlobFromSelection()` and `createTokenCanvasFromSelection()`.
- For custom frames, uses larger 1024 canvas behavior and overflow metadata.
- Custom-frame outputs disable Dynamic Ring and preserve texture scale from render metadata.

Describe persistence:

- Generated files are named with source basename, mode tag (`auto` or `manual`), timestamp, and random nonce.
- Files upload through `uploadFileToActorFolder()`.
- Generated token can replace a token image or create a token image from a portrait image.
- After save, `applyTokenImageById()` applies the generated token immediately.

### File upload and sockets

Source file:

- `scripts/utils/file-utils.mjs`

Describe:

- Allowed extensions: `webp`, `png`, `jpg`, `jpeg`, `gif`, `svg`, `avif`.
- Root upload folder: `multi-tokenart`.
- Actor folder is slugified actor name or actor id.
- GM creates folders locally.
- Non-GM can request folder creation from active GM over module socket.
- Socket request timeout is `8000` ms.
- Uploads use `FilePicker.upload("data", folder, file, { notify: false }, { notify: false })` to suppress default success toasts.
