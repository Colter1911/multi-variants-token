# Plan: guard auto token switching during Foundry transformations

## Goal
Prevent Multi Token Art auto token-image switching from overwriting an external Foundry/system token appearance change, such as polymorph, transformation, or disguise. Auto switching for that token should resume only after Foundry changes the token image back to an MTA-managed/known token image.

## Current State
- `scripts/module.mjs` schedules automation from HP/status/item/effect changes.
- `updateToken` currently ignores token `texture.src` changes unless they are HP-like delta changes.
- `scripts/logic/AutoActivation.mjs` uses the stale `activeTokenImageId` flag, so later HP/status automation can overwrite a transformed/disguised token.
- MTA writes token texture with `{ mtaManualUpdate: true }`, which is a reliable guard to distinguish MTA writes from external writes.

## Implementation Steps

1. Add token flag keys in `scripts/constants.mjs`:
   - `MANAGED_TOKEN_IMAGE_SRC: "managedTokenImageSrc"` to remember the last texture source intentionally applied by MTA.
   - `EXTERNAL_TOKEN_IMAGE_SRC: "externalTokenImageSrc"` to mark the current external Foundry/system override.
   - `PRE_EXTERNAL_TOKEN_IMAGE_ID: "preExternalTokenImageId"` to remember the active MTA token image before the external override.

2. Update `applyTokenImageById()` in `scripts/logic/AutoActivation.mjs`:
   - Whenever MTA applies a token image to an actual `tokenDocument`, also write `managedTokenImageSrc = image.src`.
   - Clear `externalTokenImageSrc` and `preExternalTokenImageId` on MTA-applied token image updates.
   - Keep existing `mtaManualUpdate: true` behavior.
   - Actor-only/prototype updates do not need external-override flags because the override is token-scoped.

3. Add helper logic in `scripts/logic/AutoActivation.mjs`:
   - `isExternalTokenImageOverrideActive(tokenDocument)` returns true only when `externalTokenImageSrc` is set and equals the token's current `texture.src`.
   - `handleExternalTokenImageChange({ actor, tokenDocument, newSrc })` processes non-MTA `texture.src` changes:
     - If `newSrc` matches `managedTokenImageSrc`, clear external flags.
     - Else if `newSrc` matches any `data.tokenImages[].src`, sync `activeTokenImageId`, update `managedTokenImageSrc`, and clear external flags.
     - Else set `externalTokenImageSrc = newSrc` and store current `activeTokenImageId` in `preExternalTokenImageId`.
   - Use `tokenDocument.update(..., { mtaManualUpdate: true })` for these flag-only bookkeeping updates.

4. Guard `runAutoActivation()` in `scripts/logic/AutoActivation.mjs`:
   - Before choosing/applying a token image, check `isExternalTokenImageOverrideActive(tokenDocument)`.
   - If active, skip token-image auto activation for that token and do not drive linked portrait from a skipped token selection.
   - Non-linked portrait automation can remain unchanged because the requirement is about token appearance; auto-rotate can remain unchanged unless later testing shows it conflicts with transformations.

5. Update `scripts/module.mjs` `updateToken` hook:
   - Import `handleExternalTokenImageChange`.
   - Add a small `hasTokenTextureSrcChange(changes)` helper checking `texture.src`.
   - In `updateToken`, after existing `mtaManualUpdate` and actor/module-flag guards, handle `texture.src` changes before HP-like changes.
   - For external texture changes:
     - Call `handleExternalTokenImageChange`.
     - If it reports reset/matched MTA image, schedule auto activation so current HP/status can re-apply the correct MTA state.
     - If it reports active external override, return without scheduling auto activation.
   - Keep HP-like scheduling unchanged for updates that do not change `texture.src`.

6. Update `CONTEXT.md` after implementation:
   - Document the new token flags.
   - Document that non-MTA `texture.src` changes suspend token-image auto activation until reset to an MTA-managed/known image.

## Edge Cases To Preserve
- MTA's own token updates must not be mistaken for external transformations because they carry `mtaManualUpdate`.
- Unlinked tokens must keep using `tokenDocument.actor`; do not replace it with `game.actors.get(actor.id)`.
- If Foundry resets to any known MTA token image, sync `activeTokenImageId` instead of leaving stale state.
- If an external override and HP/status change happen in the same token update, texture handling runs first and prevents immediate overwrite.
- Manual MTA image selection can still intentionally replace the token image and clear the external marker; this plan only blocks automatic switching.

## Verification
- Static pass: inspect all `applyTokenImageById()` callers to confirm new optional behavior does not break manager, random, createToken, or linked portrait flows.
- Manual Foundry test: apply a transformation/disguise that changes token image, then change HP/status; token image should stay transformed.
- Manual Foundry test: reset transformation/disguise; subsequent HP/status automation should resume and apply the expected MTA image.
- Manual Foundry test: create/copy a token with existing MTA flags; initial image/ring behavior should stay unchanged.
